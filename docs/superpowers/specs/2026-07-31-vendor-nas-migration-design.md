# 협력업체 NAS 폴더 → ERP 거래처DB 이관 설계

작성일: 2026-07-31

## 목표

파일서버(`\\DAWOO-SERVER`)에 폴더로만 존재하던 협력업체 102곳을 ERP `vendors` 테이블로 옮긴다.
단순 목록 이관이 아니라, 폴더 안의 사업자등록증·통장사본을 판독해 **사업자번호·대표자·주소·은행·계좌까지 채운다.**

이관이 끝나면 `/approval`(지출결의서)에서 거래처를 고르는 순간 은행·계좌·사업자번호가 자동으로 채워진다.
현재는 `vendors`에 6건뿐이고 서류 첨부가 0건이라 매번 NAS에서 통장사본을 열어 손으로 옮겨 적어야 한다.

## 소스 실태 (2026-07-31 조사)

경로: `\\DAWOO-SERVER\관리부\01. 사무관리\5. 협력업체 관련서류`

| 항목 | 값 |
|---|---|
| 하위 폴더 | 103개 (업체 102 + 양식폴더 `★협력업체서류_등록,계약서` 1) |
| 총 파일 | 635개 / 1,926MB |
| 사업자등록증류 보유 | 79개 폴더 |
| 통장사본류 보유 | 74개 폴더 |
| 둘 다 보유 | 70개 폴더 |
| 둘 다 없음 | 19개 폴더 |

용량 1,926MB 중 1,336MB(69%)는 협력업체 서류가 아니다:

- `F682D1F6.tmp`, `535455A1.tmp` — 764MB, 엑셀이 남긴 임시 찌꺼기
- `입출금내역,매입매출정산.xlsm` — 382MB, 회계자료
- `다우-산호 입,출금 거래내역.xlsm` — 96MB, 회계자료
- `매입매출정산_삼우건설.xlsm` — 95MB, 회계자료

이 4개를 빼면 실제 이관 대상은 약 590MB다.

**① 수집 후 실측 (2026-07-31)**: 여기에 `Thumbs.db` 같은 정크 97개와 20MB 초과 대용량 PDF(시공수첩 178MB, 카탈로그 75MB 등)까지 빠지면서 **업로드 대상은 624개 / 232.5MB**로 확정됐다. `documents` 버킷 현재 사용량 23.5MB를 더해도 256MB로, 무료 요금제 1GB 안에 들어간다.

`※ 미가건축` 폴더 하나에 132개 파일이 몰려 있다. 협력업체 서류함이 아니라 다른 용도로 겸용 중인 것으로 보이며, 이관 시 서류 4종만 매칭하고 나머지는 기타 파일로 넘긴다.

## 대상 / 제외

**대상**: 업체 폴더 102개

**제외**:
- `★협력업체서류_등록,계약서` — 업체가 아니라 양식 폴더
- `.tmp` 확장자 전부
- 20MB를 넘는 파일 — `vendors.note`에 NAS 경로만 기록하고 업로드하지 않는다

**NAS는 읽기 전용으로만 접근한다.** 원본 파일을 옮기거나 지우거나 이름을 바꾸지 않는다. `.tmp` 찌꺼기 삭제도 이번 작업 범위가 아니다.

## 처리 파이프라인

4단계로 나누고, ③ 승인 전에는 ERP DB·Storage에 아무것도 쓰지 않는다.

```
① 수집   NAS 스캔 → 폴더명·파일목록 JSON
② 판독   폴더명 파싱 + 서류 이미지 판독 → 필드 후보값
③ 검수   엑셀 검수표 출력 → 김태정 대리 확인·수정  ← 여기서 멈춤
④ 적재   확인된 엑셀 → vendors upsert + Storage 업로드
```

### ① 수집

`scripts/vendor-migration/scan.mjs`가 NAS를 재귀 스캔해 `scan.json`을 만든다.
각 폴더에 대해: 폴더명, 파일 목록(이름·크기·확장자·전체경로).

### ② 판독

**폴더명 → 업체명 + 공종**은 기계적 규칙으로 안 된다. 최소 6가지 형식이 섞여 있다:

| 형식 | 예 | 업체명 |
|---|---|---|
| `공종_업체명` | `갈바_성원샤링` | 성원샤링 |
| `공종,공종_업체명` | `간판,시트지,현수막_동방박사` | 동방박사 |
| `공종-업체명` | `고압호스-삼호고무` | 삼호고무 |
| `공종 업체명` (공백) | `덕트 대성덕트` | 대성덕트 |
| `공종_지역_업체명` | `방수_광명_대경실내장식` | 대경실내장식 |
| `공종_브랜드_업체명` | `보일러_경동나비엔_수원동관상사` | 수원동관상사 |
| **역순** `업체명_공종` | `한일전기_환풍기` | 한일전기 |

여기에 괄호 부가정보(`강북골재종합상사(개나리현장)`, `수호안전(김충규소장)`), 메모 삽입(`태양상사_창고임대 2024.07.01~50만원`)까지 섞인다.

따라서 **102개를 한 건씩 판단해서 매핑표를 만든다.** 사업자등록증이 있는 폴더는 등록증의 상호로 업체명을 교정한다.

폴더명 앞 `※` 표시(11개)는 의미가 확정되지 않아 **무시한다.** 별점·비고 어디에도 반영하지 않는다.

**서류 판독** — 이미지/PDF를 읽어 다음을 추출한다:

| 원본 | 추출 항목 | `vendors` 컬럼 |
|---|---|---|
| 사업자등록증 | 상호 | `name` (폴더명보다 우선) |
| | 등록번호 | `business_number` |
| | 대표자 | `representative`, `contact_person` |
| | 사업장 소재지 | `address` |
| 통장사본 | 은행명 | `bank_name` |
| | 계좌번호 | `account_number` |
| | 예금주 | (bank_info 조합에 사용) |
| 명함 (있으면) | 전화·이메일 | `phone`, `email` |

`bank_info`는 운영 데이터의 기존 형식 `은행명/계좌번호/예금주`로 조합해 함께 채운다
(예: `국민은행/264401-04-370029/기원건설`).
`bank_name`·`account_number` 정식 칼럼이 채워지면 `parseBankInfo()` 폴백은 타지 않는다 — [vendorBank.ts:3](../../../src/lib/approval/vendorBank.ts) 참조. 세 칼럼을 모두 채워 화면·결재 양쪽에서 안전하게 한다.

**추출 실패는 실패로 남긴다.** 흐릿하거나 판독이 애매하면 빈칸으로 두고 검수표에 `판독불가`로 표시한다. 추측해서 채우지 않는다.

### 공종 표준화

현재 `vendor_categories` 칩은 12개뿐이다:
금속/창호, 기와, 냉난방기, 도배, 도장/방수, 보일러, 설비, 잡부, 조적, 지게차, 철거, 타일

폴더에는 갈바·골재·폐기물·스카이·사다리차·홍보·프린터기·사원증목걸이까지 나온다. 12개에 다 들어가지 않는다.

**방침**: 기존 12개 칩은 그대로 두고, 102개 폴더의 공종을 정리해 **30~40개 표준 칩**으로 묶는다. 신규 칩은 `vendor_categories`에 추가한다. 검수표에는 `원본 폴더명 → 배정 칩`을 나란히 실어 대리님이 표에서 직접 고칠 수 있게 한다.

`vendors.category`는 자유 텍스트이므로 다중 공종은 쉼표로 잇는다 (`splitCats()`가 `,`와 `/` 모두 지원 — [VendorsPage.tsx:37](../../../src/components/vendors/VendorsPage.tsx#L37)).

### ③ 검수

`vendor-migration-검수표.xlsx` 한 장을 만든다. 102행.

| 열 | 내용 |
|---|---|
| 원본 폴더명 | NAS 폴더명 그대로 |
| 업체명 | 판독 결과 (수정 가능) |

대리님이 이 파일을 고쳐서 돌려주면, **고쳐진 값이 최종값**이다. 판독 결과로 덮어쓰지 않는다.

### ④ 적재

**Storage 경로**: `documents` 버킷의 `vendors/{vendor_id}/{연번}_{안전화된파일명}`
`safeStoragePath()`와 동일 규칙으로 한글·특수문자를 `_`로 치환한다 ([storagePath.ts:11](../../../src/lib/utils/storagePath.ts#L11)). 원본 파일명은 DB에 따로 보관한다.

일회성 이관 스크립트는 `SUPABASE_SERVICE_ROLE_KEY`로 supabase-js Storage 클라이언트를 직접 쓴다.
`/api/storage/upload`는 `getAuthUser()` 로그인 세션을 요구하고 20MB·MIME 화이트리스트 제한이 있어 배치에 맞지 않는다. 대신 스크립트가 `safeStoragePath()`와 `vendors/` 프리픽스 규칙을 그대로 지킨다.
(앱 화면에서의 업로드는 지금처럼 `/api/storage/upload`만 쓴다 — 이 예외는 이관 스크립트 한정이다.)

**서류 4종 슬롯**: `biz_license_url`, `bankbook_url`, `id_card_url`, `safety_cert_url` — 파일명 매칭으로 채운다.

**기타 파일**: 나머지 약 500개 파일은 넣을 칸이 없다. 새 테이블을 만든다.

```sql
-- 017_vendor_files.sql
CREATE TABLE IF NOT EXISTS vendor_files (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  vendor_id UUID NOT NULL REFERENCES vendors(id) ON DELETE CASCADE,
  file_name TEXT NOT NULL,        -- 원본 파일명 (한글 그대로)
  file_url TEXT NOT NULL,
  storage_path TEXT NOT NULL,
  size_bytes BIGINT,
  source_path TEXT,               -- 원본 NAS 경로
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS vendor_files_vendor_id_idx ON vendor_files(vendor_id);

-- RLS는 켜지 않는다.
-- 프론트(src/lib/supabase.ts)가 세션 없는 anon으로 요청하므로 authenticated 전용 정책을 켜면
-- 화면에서 조회가 차단된다. 009_vendor_categories_rls_off.sql과 같은 이유.
ALTER TABLE vendor_files DISABLE ROW LEVEL SECURITY;
```

`VendorsPage` 상세 모달에 **기타 서류** 목록 섹션을 추가한다 (파일명 + 다운로드 링크 + 삭제). 기존 `FileDropZone` 4종 아래에 붙인다.

### 중복 병합

기존 `vendors` 6건 중 5건이 NAS 폴더에도 있다: 기원건설, 미가건축, 신도오피스넷(`복사기렌탈-신도오피스넷`), 노나(`주식회사 노나`), 두인건설(`주식회사 두인건설`).

매칭은 **업체명 정규화 후 비교**한다: 공백·`주식회사`·`(주)` 제거 후 대조. 애매하면 자동 매칭하지 않고 검수표에 후보로만 표시한다.

**병합 규칙: 기존 값이 있으면 유지하고 빈칸만 채운다.** 기존 입력을 덮어쓰지 않는다. 서류 URL과 기타 파일은 기존 행에 추가로 붙인다.

## 안전장치

- ③ 승인 전에는 DB·Storage 쓰기 없음
- 적재 직전 `vendors` 전체를 JSON으로 백업 (`backup/vendors-YYYYMMDD.json`)
- 적재는 새로 만든 행의 id 목록을 `migration-log.json`에 남긴다 → 되돌릴 때 그 id만 삭제하면 원상복구
- NAS 원본 무변경 (읽기만)
- `.env.local`의 키는 스크립트에서 읽기만 하고 로그·엑셀에 남기지 않는다

## 선행 확인

**Supabase 요금제.** ~~무료 요금제는 Storage 1GB다.~~ **확인 완료 (2026-07-31)** — 현재 `documents` 버킷 사용량 23.5MB + 이관 232.5MB = 256MB로 무료 요금제 1GB 안에 여유 있게 들어간다. 요금제 변경 없이 진행 가능.

## 하지 않는 것

- NAS 파일 삭제·이동·정리 (`.tmp` 찌꺼기 포함)
- 일용직 이관 — 이 폴더는 협력업체 전용이다. 전부 `vendor_type='협력업체'`
- `※` 표시의 별점·비고 반영
- 계약서 내용 판독 (금액·기간 등) — 파일 업로드까지만
- NAS ↔ ERP 양방향 동기화. 이번은 **일회성 이관**이다
