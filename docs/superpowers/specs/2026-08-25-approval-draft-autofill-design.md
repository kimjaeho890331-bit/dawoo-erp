# 지출결의서 기안 자동화 설계

작성 2026-08-25.

기안작성 화면에서 손으로 반복하던 세 가지를 자동으로 채운다. 현장을 고르면
기안제목이, 거래처를 고르면 그 업체 서류가 따라온다. 결재선 후보 목록은 실제로
자주 쓰는 순서로 세운다.

## 배경

현재 기안작성은 같은 내용을 매번 손으로 넣는다.

- 기안제목은 사실상 정해진 꼴이다. 실제 문서를 보면 `{현장} {거래처} 집행 요청의 건`이
  대부분인데(`정자1동 행정복지센터 대원상사(방수,도장) 집행 요청의 건`), 현장을 이미
  화면에서 골라놓고도 제목에 다시 타이핑한다.
- 결제를 올릴 때 필요한 서류 다섯 가지 중 **사업자등록증·통장사본은 이미 거래처DB에
  등록돼 있다.** 그런데 첨부는 다섯 개를 모두 손으로 올린다.
- 결재선 후보 목록은 이름 가나다순이라, 자주 고르는 사람을 매번 찾아야 한다.

## 범위

세 가지는 서로 독립적이다. 순서대로 따로 구현하고 따로 검증할 수 있다.

### 1. 현장 선택 → 기안제목 자동입력

`WorkTargetPicker`에서 대상을 고를 때 **기안제목이 비어 있으면**
`{대상 이름} 집행 요청의 건`으로 채운다.

- 이미 입력된 제목은 건드리지 않는다. 손으로 고친 제목이 대상을 바꿨다고 날아가면 안 된다.
- 50자를 넘으면 잘라낸다. 입력칸이 원래 50자 제한이라 규칙을 맞춘다.
- **현장(sites)과 접수건(projects) 모두 적용한다.** 실제 제목에 접수건 이름도
  쓰이기 때문이다(`화성 공용수도 대광빌라 F동(16세대) 한경건설기계 집행 요청의 건`).
- 가운데 거래처명은 기안자가 직접 끼워 넣는다. 자동으로 조합하지 않는다 —
  거래처를 나중에 바꾸면 제목이 어긋나고, 그 동기화 규칙이 이득보다 복잡하다.

### 2. 결재선 후보 목록 순서

`ApprovalLineModal`의 왼쪽 후보 목록 정렬을 이름순에서 고정 순서로 바꾼다.

    조혜진 → 송승란 → 김용이 → 김재호 → 김지선 → (나머지 이름순)

- **후보 목록의 표시 순서만 바꾼다.** 실제 결재 순서(`expense_report_lines.seq`)는
  지금처럼 오른쪽 패널에 추가한 순서로 정해진다. 결재 로직은 손대지 않는다.
- 순서는 코드 상수(이름 배열)로 둔다. 직원 12명 규모에서 이게 가장 단순하다.
  화면에서 순서를 조정하고 싶어지면 그때 `staff`에 정렬 컬럼을 두는 게 맞지만,
  지금은 과하다.
- 목록에 없는 이름은 뒤쪽에 이름순으로 붙는다. 신규 입사자가 사라지지 않게.

### 3. 거래처 선택 → 서류 자동 첨부

지급정보에서 거래처를 고르면 그 업체의 **사업자등록증·통장사본**이 첨부 목록에
자동으로 올라온다.

- 파일을 복사하지 않는다. 거래처DB에 저장된 URL을 그대로 가리키는 행만 만든다.
- **자동 첨부는 추가만 한다.** 거래처를 바꿔도 이전 서류를 자동으로 떼지 않는다.
  자동 제거는 기안자가 직접 올린 파일을 잘못 날릴 위험이 있다. 필요 없으면 X로 지운다.
- 같은 파일이 두 번 붙지 않게 URL로 막는다.
- 거래처DB에 서류가 없으면 아무것도 붙지 않는다. 오류로 취급하지 않는다.
- 직접 첨부는 지금과 똑같이 동작한다. 전자세금계산서·거래명세서·견적서는
  기안자가 올린다.

## 영수증 선정 규칙

승인 시 지출이 자동 생성되면서 첨부 **한 개**가 그 지출의 영수증
(`expenses.receipt_url`)으로 저장된다. 현재 규칙은 "가장 먼저 올라온 첨부 1건"이다.

자동 첨부를 켜면 거래처 서류가 항상 먼저 올라오므로, 그대로 두면 **사업자등록증이
영수증으로 기록된다.** 실무상 영수증은 전자세금계산서여야 한다.

그래서 `expense_report_files`에 출처 컬럼을 추가한다.

    source TEXT NOT NULL DEFAULT 'manual'   -- 'manual' | 'vendor'

- 승인 시 영수증은 `source = 'manual'` 중 가장 먼저 올라온 것으로 고른다.
- 직접 올린 파일이 하나도 없으면 영수증은 비운다(null). 거래처 서류를 영수증으로
  쓰지 않는다.
- 이 컬럼은 화면 배지("거래처" 표시)에도 그대로 쓴다. 자동 첨부를 만들면 어차피
  출처 구분이 필요하므로 추가 비용이 사실상 없다.
- 기존 행은 기본값 `'manual'`로 채워진다. 지금까지 올라온 첨부는 전부 직접 올린
  것이므로 사실과 맞는다.

`receipt_url`은 현재 어느 화면에도 표시되지 않는다. 즉 이 규칙은 당장 눈에 보이는
동작을 바꾸지 않고, 나중에 영수증 보기 기능을 만들 때 데이터가 맞아 있게 하는 것이
목적이다.

## 영향 범위

| 대상 | 영향 |
|---|---|
| 결재 순서(`seq`)·승인·반려·회수 | 없음 |
| 승인 → 지출 자동등록 | 지출 제목이 새 제목 규칙을 따른다. 영수증은 정확해진다 |
| 결재 알림 문구 | 제목이 그대로 들어가므로 문구가 바뀐다 |
| 기존 문서 | 없음. 새로 작성할 때만 동작한다 |
| 임시저장·재상신·엑셀 업로드 | 없음 |
| 거래처DB | 읽기만 한다. 수정하지 않는다 |

## 검증

- 제목: 대상 선택 시 채워지는지, 이미 쓴 제목이 보존되는지, 50자 초과 시 잘리는지
- 결재선: 후보 목록 순서, 목록에 없는 직원이 뒤에 붙는지, 결재 순서가 그대로인지
- 자동 첨부: 서류 있는 거래처·없는 거래처, 중복 방지, 직접 첨부와 섞였을 때
- 영수증: 자동+직접이 섞인 문서를 승인했을 때 직접 올린 첫 파일이 선택되는지,
  직접 첨부가 없으면 null인지
- `paymentsToExpenses` 단위 테스트에 영수증 선정 케이스를 추가한다

## 하지 않는 것

- 거래처 변경 시 이전 서류 자동 제거
- 제목에 거래처명 자동 조합
- 신분증·안전교육증 자동 첨부 — 결제 서류가 아니다
- 결재 순서(seq) 자동 지정
